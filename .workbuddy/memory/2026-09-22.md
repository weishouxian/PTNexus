## 馒头（M-Team）作为**源站**接入：SPA 站拉种拿不到下载链接

**问题**：转种/迁移批次里 `[迁移-种子下载] source_site=馒头` 打出 `详情页解析成功 html_len=10277 新增候选=0` → `下载候选为空 原因=详情页无有效链接`，随后 `[发布-详情回写] ... hashes=[]`，种子进不了下载器。

**根因**：馒头详情页是 SPA（`/detail/{id}`），HTML 里没有任何 `.torrent` 链接。YemaPT 早就有同类分支，馒头没接。

**改动（5 个文件 + 1 个新包）**
- 新增 `server/internal/service/mteamapi/`（叶子包，发布适配器与源站下载共用）：
  - `credential.go`：`ExtractToken` / `ResolveToken` / `Fingerprint` / `IsSite` / `ExtractTorrentID`
  - `api.go`：`Response`（code 兼容字符串/数字）、`APIBaseFor`（env `MTEAM_API_BASE` 可覆盖）、`GenDlToken`、`BodySnippet`
- `publish/publisher/sites/mteam.go`：删掉本地重复实现，改为委托 `mteamapi`（保留 `resolveMTeamToken` / `mteamTokenFingerprint` 薄封装供测试）
- `acquire/fetch/torrent_fetch.go`：新增 `isMTeamSource` + `resolveMTeamSourceDownloadURL`；`isSPADetail` 合并跳过 HTML 解析；`buildDirectDownloadURL` 对 m-team 返回空（避免假 `download.php` 候选）；`buildDetailURL` 补 `/detail/{id}`；「候选内容无效」日志改为附带响应体摘要与站点 message
- `repository/site_repository.go`：`ListSourceAndTargetSites` 源站侧过滤改为 `cookie 非空 OR passkey 非空`（与 `PrepareSourceSite` 对齐）
- `server/sites_data.json`：m-team `migration` 2 → 3

**关键事实（下次直接用）**
- 换直链：`POST {apiBase}/api/torrent/genDlToken`，头 `x-api-key`，multipart 字段 `id`；响应 `data` 是 `/api/rss/dlv2?sign=..&t=..&tid=..&uid=..`，会 **302 到下载网关 `fr1.halomt.com`**，跟随跳转才拿到 `.torrent`。Go 的 http.Client 自动跟即可（跨域丢 Cookie/Referer、留 UA），已实况验证 34743 字节 + `ParseTorrentMeta` 通过。
- 不需要 `authorization` JWT（回了「非法用戶端」），也不需要前端的 `_sign`/`_timestamp`。
- ⚠️ **同一顆種子每天最多下载 10 次**；超限仍是 **HTTP 200**，错误在 JSON 体（`{"code":"1","message":"相同種子當天最多下載10次"}`）。排查时别反复试同一个种子（本次把 1257835 的配额耗尽了，只能换 1255665 验证）。
- `acquire/fetch` **不能** import `publish/publisher/sites`（publish 已 import fetch，会成环）→ 公共逻辑必须放第三方叶子包。

**验证**：`mteamapi` 5 组单测、`fetch` 6 组单测（含 httptest 端到端复现换直链→302→网关）、sites 配置单测全绿；`go build ./...` 通过；gofmt 通过（顺手修了 `mteam.go` 里 `mteamDefaultConfig` 一处对齐）；live probe 验完删除。

## 馒头发种：站点报「種子已存在」应记为 exists 而非 failed

**根因**：`sites/mteam.go` 已用 `isMTeamDuplicateMessage` 判定并回传 `IsExistingTorrent=true`，但 `publish/workflow/publish_target.go` 在 `publishErr != nil` 分支**直接返回 error**，把已存在当硬失败；下游 `publish_entry.go` 走 500/success=false → `appendPublishLog` 的 `logStatus` 只在 `statusCode==200 && success` 时才可能取 exists，于是落成 failed。

**改动（2 文件）**

## 馒头发种：简介图片改回 BBCode + 标题「UHD BluRay」纠偏

**问题 1（图片）**：馒头发出的简介里图片是 Markdown 写法（`![_](url)`），站点显示不出来。
**根因**：`sites/mteam.go` 的 `buildMTeamDescription` 当初假定「站点简介是 Markdown 编辑器」，主动把上游的 `[img]url[/img]` 转成了 Markdown。
**改动**：改为统一输出 BBCode `[img]url[/img]` —— 去掉 `[img=600]` 一类宽度属性、URL 为空的标签直接删除、并把历史 Markdown 写法 `![alt](url)`（新增 `reMTeamMarkdownImg`）一并归一为 BBCode。其余正文原样保留。

**问题 2（标题）**：馒头站点规范里 UHD 蓝光写作「UHD BluRay」，实际发出的是「UHD Blu-ray」。
**根因**：标题写法**沿用源标题**（`processing/title/components.go` 的 `PreferredBlurayTokenFromTitle` 特意保留源自标题的 `BluRay`/`Blu-ray` 变体），源站写连字符时发到馒头就违规范。
**改动**：`sites/mteam.go` 新增 `reMTeamUHDBluray`（`(?i)\bUHD[ \t]+Blu[-\s]?ray\b`）+ `normalizeMTeamTitle(title)`，在 `PublishMTeam` 取标题处调用 → 统一替换为 `UHD BluRay`。幂等（已是正确写法不变）、大小写/多空格都能纠；**只动 UHD token，普通 `1080p Blu-ray` 不碰**（用户只报了 UHD 这一处）。日志里的 `name=%q` 显示的就是纠偏后的标题。

**测试**：新增 `mteam_format_test.go`（`buildMTeamDescription` 8 组 + `normalizeMTeamTitle` 8 组），sites 包 4 个测试全绿。

**边界**：纠偏只在 m-team 适配器内做（站点级），**不影响本地库标题与其它站点**。若以后要让本地标题/其它站也统一写 BluRay，得改 `processing/title` 的 `PreferredBlurayTokenFromTitle` 或 `global_mappings.yaml` 反向映射 —— 本轮未做。

**验证**：`go -C server build ./...` 通过；`go vet ./internal/service/publish/...` 通过；`go test ./internal/service/publish/... ./internal/service/processing/...` 全绿；gofmt 干净。

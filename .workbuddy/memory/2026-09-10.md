## 修复：官组致谢对 DepWeb/DS 合并站点不赋值申明

- 现象：日志 `迁移-官组致谢 官组致谢结果 applied=false reason=未找到制作组显示名 statement_len=0`。
- 根因：`server/internal/service/processing/acknowledgment/team_ack.go` 的 `pickTeamDisplayName`：
  - DS 站点行 `group="-DStudio,-DS,-DepWeb"` 但 `description=''`（迁移 INSERT 可见），原逻辑 `if desc=="" ... continue` 直接跳过整行；
  - 命中后 `return desc` 返回站点 description，合并站点下非主组会拿到错误/空名字。
- 修复：命中 group token 后改 `return original`（即 `team.depweb` 经 global_mappings 反查得到的 `DepWeb` 显示名），并去掉"desc 为空跳过"的限制。单组站点（HDSky 等）行为不变。
- 验证：临时单测用真实 DS 行确认返回 `DepWeb` 且生成 `[quote]…DepWeb官组作品…[/quote]`；`go vet` 通过。
- 注意：DS 站点 `description` 为空现在对该功能无害，未改数据；改动仅停留在当前分支工作区，未提交。

## 修复：sites 同步时 description 被空值覆盖

- 用户要求：重同步时不要让 `sites_data.json` 里未配置 description 的站点把库里手动值清成 NULL。
- 根因：`server/internal/repository/sites_sync.go` 的 `SyncSitesFromJSON` UPDATE 分支无条件写 `description = nullIfEmpty(jsonDesc)`；`jsonDesc` 为空（JSON 没配）时就把 DB 值覆盖成 NULL。
- 改法：
  - `existingSiteRow` 增加 `Description` 字段，SELECT 读出已有值；
  - UPDATE 分支新增 `finalDescription`：仅当 `jsonDesc != ""` 才用 JSON 值，否则保留 `matched.Description`；
  - 写入参数与 `matched.Description` 同步改用 `finalDescription`。
- 验证：`go vet` + `go build` 通过；`go fmt` 已统一缩进。改动仅停留在当前分支工作区，未提交。

## 修复：发布后源站种子地址被覆盖成目标站地址

- 现象：转种/发布成功后，源站那一行种子的"详情链接"(torrents.details)变成目标站发布地址。
- 根因：`publish_entry.go` 发布成功后回写 `torrents.details` 时，`publishedHashCandidates` 默认用 `input.SourceTorrentHash`（源站 hash）初始化；`migrate_repository.go` 的 `UpdateTorrentDetailsAfterPublish` 在 `sites=目标站` 过滤未命中后，又用"去站点过滤、仅按 hash"的兜底 UPDATE，按源站 hash 命中源站行并 `SET details=目标站地址`，且无条件覆盖（不像 IYUU 回填那样判空）。
- 改法：
  - `publish_entry.go`：`publishedHashCandidates` 改为空切片起手，只收录自动加下载器后由下载器返回的目标种子 hash；删除随之无用的 `collectPublishedTorrentHashes` 函数。
  - `migrate_repository.go`：删除"去站点过滤按 hash 兜底"那段，只保留 `sites=目标站` 的精确更新。
- 验证：`go build ./internal/service/publish/workflow/... ./internal/repository/...` 通过。改动仅停留在当前分支工作区，未提交。

## 发种：铂金家(pthome)发布后直链下载加 downhash 参数

- 用户要求：参考杜比(hddolby)下载种子的方法，铂金家(pthome)发布后直链下载地址也要加 `downhash` 参数，并在站点设置里为铂金家也能配置该参数。
- 现状：杜比的 downhash 机制在 `BuildDirectDownloadURLForPublished`（发布流程回退构造直链），`hddolby` case 输出 `download.php?id=X&downhash=<passkey>`，passkey 字段存 downhash 值（SitesSettings.vue 有提示）。pthome 没有该 case，落到默认 `&passkey=`。
- 改动（参考杜比、复用 passkey 字段，零 DB 改动）：
  - `server/internal/service/publish/uploader/published_url.go`：switch case 由 `"hddolby"` 改为同时命中 `"hddolby"` 与 `"pthome"`，均输出 `&downhash=<passkey>`。
  - `webui/src/components/settings/SitesSettings.vue`：passkey 字段提示 `v-if` 增加 `|| siteForm.site === 'pthome'`，文案改为"杜比/铂金家"。
- 安全性：pthome `migration=2`（非迁移源，源需 1/3），且通用发布器不上传用 passkey，复用 passkey 作 downhash 不影响其它逻辑。
- 验证：`go build ./...` 与 `pnpm run type-check` 均通过。改动仅停留在当前分支工作区，未提交。

## 新功能：下载器种子地址反查（hash 反查站点下载直链）

- 背景：下载器 API（qB `torrents/info` / Transmission `torrent-get`）不返回种子源地址，`TorrentSnapshot` 也没有 URL 字段；只有经 AutoSeed/RSS 录入的种子才有 `torrent_url`。用户要求实现反查。
- 方案：tracker/站点列表匹配 → 站内搜索种子名（`torrents.php?search=X&search_area=0`）→ 逐候选下载 .torrent 并用 `ParseTorrentMeta` 比对 info_hash → 命中返回下载直链。
- 改动文件：
  - `server/internal/service/acquire/fetch/public_wrappers.go`（新增）：导出 `FetchBinaryWithCookie` / `BuildDirectDownloadURL` / `ExtractDownloadCandidatesFromDetail` / `IsLikelyTorrent` 包装。
  - `server/internal/repository/torrent_data_repository.go`：新增 `GetSiteConnectionByName`（读 cookie/passkey/base_url）。
  - `server/internal/service/torrentdata/torrent_url_resolver.go`（新增）：`TorrentDataService.ResolveTorrentURL`，候选站点最多 3 个（refreshSiteMatcher 匹配 + 请求携带 sites），搜索候选最多 5 个，Cookie 失效返回 `ErrSourceCookieExpired` 友好提示。
  - `server/internal/service/torrent_data_service.go`：类型别名导出。
  - `server/internal/http/handler/torrents_data_handler.go` + `bootstrap/app.go`：新端点 `POST /api/data/resolve_torrent_url`。
  - `webui/src/views/TorrentsView.vue`：操作列加「地址」按钮（宽 150→200），点击调接口，命中后复制直链到剪贴板（失败则弹窗展示）。
- 验证：`go build ./...`、`go vet` 相关包、`pnpm run type-check` 均通过。改动仅停留在当前分支工作区，未提交。
- 限制：v1 仅适配 NexusPHP 风格搜索页；rousi/ttg 等特殊直链格式已由 `BuildDirectDownloadURL` 覆盖但搜索页路径相同（若站点搜索结构不同会解析不到候选，属预期失败路径）。

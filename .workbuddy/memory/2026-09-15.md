## 修复 auto-seed 规则保存时 MySQL Error 1292（next_run_at 时间格式）

- 现象：`PUT /api/auto-seed/rules/:id` 报 `Error 1292 (22007): Incorrect datetime value: '2026-09-15T14:40:11Z'`，因前端回传的 `next_run_at` 是 ISO 8601（带 `T`/`Z`），MySQL DATETIME 不接受。
- 修复：把 `scheduled_seed_repository.go` 的 `normalizeNextRunAt` 导出为 `NormalizeNextRunAt`（其两处调用同步改名），并在 `service/autoseed/service.go` 的 `normalizeRule` 中对 `rule.NextRunAt` 调用它，统一归一化为 `2006-01-02 15:04:05`。新建/更新两条路径都经 `normalizeRule`，故均覆盖。
- 本地无 Go 工具链，无法编译；改动完全照搬 scheduled-seed 既有写法，需在部署服务端 `go build` 或走 ptn-deploy 验证。

## 修复【影片参数】截断只在发布时生效、UI 展示的简介仍含冗余段

- 根因：上一轮只在发布出口（`uploader.BuildUploadDescription` 与 `public_site.go:50`）清洗，而 hdsky 等源站提取的 `Intro.Body`（即 UI 里看到的"简介信息"）在 `SeedData.Normalize` 阶段未清洗，所以展示/存储的原始文本仍带 `[color=blue][b]【影片参数】[/b][/color]` 及之后的 mediainfo/截图。
- 修复：新建叶子包 `internal/service/descclean`（仅依赖标准库，避免 extract↔publish 循环依赖），统一放 `TrimDescriptionAtMovieParams`；在 `acquire/extract/sites/types.go` 的 `SeedData.Normalize` 中对 `Intro.Body`/`Intro.Statement` 清洗（抓取即清，展示与发布一致）；`uploader/helpers.go` 的 `TrimDescriptionAtMovieParams` 改为委托 `descclean`（单一真源，删本地正则副本）。
- 边界：正则兼容 `[color...][b]【影片参数】` 与 `[b][color...]【影片参数】` 两种顺序，从首个开启标签截断避免悬空标签；纯文本 `【影片参数】` 仍有回退。
- 编译/测试：`go build ./internal/service/descclean/... ./internal/service/acquire/extract/... ./internal/service/publish/...` 通过；`descclean` 与 `uploader` 单测全过（含 b-在外的用例）。

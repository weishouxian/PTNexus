## 抓取标题清洗：新增前缀中文片名剥离

- 需求：标题形如 `焦点Focus Blu-ray 2015 1080p Blu-ray AVC DTS-HD MA 7.1-52pt`，前面的中文片名「焦点」要去掉。
- 实现（与上一条尾部徽标同一组清洗链路）：
  - `server/internal/service/acquire/extract/review_extract.go`：新增 `reLeadingChineseTitle` 正则与 `stripLeadingChineseTitle`，在 `cleanTopTitleText` 返回前调用（`extractTopTitle` 通用路径，覆盖大多数 NexusPHP 站点）。
  - `server/internal/service/acquire/extract/sites/ssd.go`：新增同规则的 `reSSDLeadingChineseTitle` + `stripSSDLeadingChineseTitle`，`extractSSDTitle` 两个返回点各包一层。
- 判定规则（关键）：`^([\p{Han}·・]+)[\s\x{3000}]*([A-Za-z].*)$` —— **中文段之后必须紧跟 ASCII 字母**才剥离。因此：
  - `焦点Focus …` / `焦点 Focus …` / `流浪地球The Wandering Earth …` → 剥离 ✓
  - `庆余年 2019 1080p`（中文后接数字）→ 不动 ✓
  - 纯中文标题 → 不动 ✓（不会剥空）
  - ⚠️ 副作用：`加长版 Extended Cut` 这类「中文修饰词+英文」也会被剥掉修饰词，属可接受但需留意。
- Go RE2 **不支持前瞻**，故用捕获组 `([A-Za-z].*)` 代替 `(?=[A-Za-z])`。
- 验证：临时测试 8 例（含用户样本、空格分隔、尾部徽标共存、纯中文/中文+数字不误伤），`go test -run ZZTmp` 全绿；已备份 `.workbuddy/tmp/test-backup/*leading_cn_title_test.go.20261008` 后删除；`go build ./...` + `go vet ./internal/service/acquire/...` 通过。
- ⚠️ 本次跑了 `gofmt -w`，var 块 `=` 对齐被重排（两个文件在 HEAD 上本就不满足 gofmt，纯空白差异）；行尾按约定 `tr -d '\r'` → gofmt → `sed 's/$/\r/'` 恢复 CRLF。

## 修复 dupe「0 结果被误判成异常页面」（用户报的家园发布失败）

- 现象：家园搜 IMDb tt12446086 返回 0 条，却报「dupe 检索返回的页面不含结果列表，无法确认是否重复」→ 发布直接失败。用户指出：**搜不到结果就等于没有重复**。
- 根因：`rejectUnexpectedPage` 用结果表标记（`class="torrents"` / `id="torrenttable"`）判定「是否正常结果页」，但**站点在 0 条结果时本就不渲染结果表** → 正常无结果被判成异常页。三处调用点（audiences/luckpt/nexusphp）外加两段重复的同逻辑兜底，全都有这个错。
- 实测对照（hdhome，`tt99999999` vs `tt12446086` vs 失效 Cookie）：
  | 场景 | len | title | class="torrents" | name="search" | name="username" |
  |---|---|---|---|---|---|
  | 0 结果 | 54604 | 搜索结果 - tt99999999 | **0** | **1** | 0 |
  | 有结果 | 63139 | 搜索结果 - tt12446086 | 1 | 1 | 0 |
  | Cookie 失效 | 7005 | **登录** | 0 | 0 | **1** |
  → **「是否有搜索表单」是区分「真的没有重复」与「登录/限流导致查不到」的关键特征**；chdbits 的 0 结果页同样带 `name="search"`/`name="search_area"`/`id="searchinput"`，判据通用。
- 修复（`dupe/search.go`）：`rejectUnexpectedPage` 重写为 `ensureSearchResultPage(body, resultTableMarkers)`，四态判定 ——
  1. 登录页 → 报错（Cookie 失效，查不到 ≠ 不重复）；
  2. 限流/人机验证页 → 报错；
  3. 有结果表标记 → 正常（交给解析，可能有候选）；
  4. 否则**有搜索表单** → 正常（站点处理了搜索但 0 条 → 「没有重复」）；
  5. 都没有 → 报错（非预期页面）。
  三处调用点统一改为调用它，并删掉各自那段「无结果表即报错」的重复兜底；顺手删除已成死代码的 `audiencesDupeResultTablePattern`。
- 验证：临时测试 4 例（0 结果页放行 / 登录页·限流页·未知页仍报错且文案对应 / 有结果表放行 / **真实 hdhome 0 结果链路不报错**——URL 里正是用户日志中的 `cat450`，完整复现）全绿，已备份 `.workbuddy/tmp/test-backup/` 后删除。`go build ./...` + `go vet ./...` 干净，4 个改动文件 gofmt 通过。
- 注意：这条修复与上一轮的「带筛选 0 候选 → 去掉筛选重试」形成配合——0 结果会先触发退化重试，两层都不报错才算「无重复」。

## 诊断 g9 服务器卡死（根因：qbittorrent-nox 内存失控 → 全局 OOM）

- 现象：用户提供 `diag-freeze.sh`（root@g9:/data）输出，机器频繁卡死；9 天半内 29 次 OOM。
- 根因：`seedbox-qbittorrent-user15.service` 内的 qbittorrent-nox 堆内存涨到 6.5–7.0 GiB（anon-rss，file-rss≈0 说明是堆而非 mmap），把 7.8 GiB 机器吃光；该服务**无 cgroup 内存上限**，日志出现 `constraint=CONSTRAINT_NONE` + `global_oom` → 内核走全局 OOM（触发者是 `1panel.service` 与 `sshd-auth`，`order=0` 单页分配都失败），整机在 direct reclaim/换页抖动中卡死。两次快照 total-vm 从 7.1 GiB 涨到 11.4 GiB → 更像配置过大/无界增长而非固定缓存。
- 排除项：磁盘 71%（89G 空闲，不是原因）；Docker 仅 mysql 51 MiB + vertex 7 MiB。次要隐患：两个容器都无内存限制。
- 修复方案（已写成报告，含可直接粘贴命令）：
  - P0 用 `/etc/systemd/system/seedbox-qbittorrent-user15.service.d/limits.conf` 设 `MemoryHigh=3G / MemoryMax=4G / MemorySwapMax=512M / OOMPolicy=continue` → 全局 OOM 降级为局部 OOM；
  - P0-b 装 earlyoom（`-m 8 -s 5`）抢在内核 OOM 前动手；
  - P1 收紧 qBittorrent 连接数/上传槽/磁盘缓存（固定 256 MiB，别用自动）/活动种子数，并记录 qbittorrent+libtorrent 版本；
  - P1-b 上 zram（zstd, PERCENT=50）替代磁盘 swap；P2 给 mysql/vertex 补 mem_limit；P3 建 RSS 趋势采集（/usr/local/bin/qbit-rss.sh + /etc/cron.d/qbit-rss）。
- ⚠️ 顺带发现 `diag-freeze.sh` 第 126/142/154 行报 `[: 0\n0: integer expression expected`：变量含两行，最可能是 `grep -c` 一次匹配多个文件（grep -c 多文件按文件各输出一行）。**后果是 conntrack 满 / 文件系统错误 / 任务挂起三项检查实际未生效，那些 ✅ 是假阴性**；汇总里重复打印也是同一原因。修法：`grep -ch ... | awk '{s+=$1} END{print s+0}'` 或用 journalctl 收口；另第 2 节「Swap 已用 616MB → ✅ 正常」判据有误。

## YemaPT 作为源站下载种子（修复「详情页无有效链接」）

- 现象：`[迁移-种子下载] [下载候选为空] source_site=YemaPT torrent_id=https://www.yemapt.org/#/torrent/detail/14887 原因=详情页无有效链接`。
- 根因：`DownloadTorrentForSource` 走的是 NexusPHP 通用链路——把 torrentID 当详情页地址直接抓 HTML 再正则提取下载链接。YemaPT 是 UmiJS SPA，请求 `/#/torrent/detail/14887` 只会拿到前端壳 HTML（hash 片段甚至不发给服务端），永远解析不出链接。
- 正确机制（用户抓包确认）：
  1. `GET /api/torrent/generateDownloadKey?id={id}` → `{"success":true,"data":"<token>"}`
  2. 直链 = `GET /api/torrent/download1?token=<token>`（token 原样拼接，base64，不做 URL 转义）
- 改动 `server/internal/service/acquire/fetch/torrent_fetch.go`：
  - 新增 `reYemaPTDetailID`（`/torrent/detail/{id}`）、`isYemaPTSource()`（按 site 代码或域名识别）、`extractYemaPTTorrentID()`、`resolveYemaPTDownloadURL()`（换 token 拼直链）。
  - `DownloadTorrentForSource`：yemapt 走 API 直链候选，并**跳过** SPA 详情页的 HTML 抓取（省一次无意义请求，也避免误判 cookie 失效）。
  - `buildDetailURL`：yemapt 裸 ID → `{base}/#/torrent/detail/{id}`。
  - `buildDirectDownloadURL`：yemapt 直接返回空，避免生成无效的 `download.php?id=` 候选。
  - 空候选时的日志区分出 `原因=YemaPT 接口未返回下载 token`。
- 新增单测 `server/internal/service/acquire/fetch/torrent_fetch_yemapt_test.go`（ID 提取 6 例 / 站点识别 5 例 / 详情 URL 2 例 / 直链守卫 1 例），全部通过；`go build ./...`、`go vet`、`go test ./internal/service/acquire/... ./internal/service/publish/...` 全绿。
- 注：上一轮 `/detail` 修正已被用户提交（HEAD 现为 `12ddba1`）。本轮改动未 commit。

## YemaPT 发布「中国种子发成美国地区」根因（字典键与标准化值前缀不一致）

- 现象：种子产地 = 中国（`产地 = source.china`），但发布到 YemaPT 时地区选了美国。
- **根因：yemapt.yaml 的键写法与 PTNexus 标准化值不匹配。**
  - 标准化值形如 `source.china` / `category.tv_series` / `video.h265`（前缀 + 后缀，见 `configs/global_mappings.yaml`）。
  - `pickYemaPTValue` 先按完整值查、再去掉第一个 `.` 前缀用后缀查，都未命中就**静默回落 `defaults`**。
  - region 字典只写了 `cn`，而实际后缀是 `china` → 未命中 → 回落 `defaults.region = "4"`（美国）。
- 同类缺陷（顺带排查出，均已修或明确标注）：
  - `category`：只有 `movie`，实际是 `category.tv_series` → **电视剧会被发成电影(4)**。tv_series 的真实 value 还没抓，先不配置 + 告警。
  - `codec`：写的是 `x265`/`hevc`，实际后缀是 `h265`/`h264` → HEVC 靠「回落值恰好等于 2」蒙对，**H.264 会被标成 HEVC**。已补 `h265: "2"`，`h264` 待抓。
  - 命中的：`medium.webdl`→suffix `webdl` ✓、`audio.aac`→`aac` ✓、`resolution.r2160p`→normalize 去前缀 ✓、`video.h265`→现在 ✓。
- 改动：
  - `server/configs/yemapt.yaml`：region 补 `source.china: "1"` / `china: "1"`；codec 补 `h265: "2"`；各段补「键必须写去前缀形态」的说明；defaults 上方说明未命中会告警。
  - `server/internal/service/publish/publisher/sites/yemapt.go`：
    - `pickYemaPTValue` 重构为 `pickYemaPTValueEx(...) (string, bool)`（返回是否命中），并删除旧包装函数；
    - `PublishYemaPT` 内所有维度（category/medium/standard/codec/audio/region）统一走一个 `pick` 闭包，**未命中就在发布日志逐条打印 `⚠️ xx 映射未命中：标准化值 "..." 已回落默认值 N`**，不再静默发错值（team 保持原语义不告警）；
    - 内置 `yemaptDefaultConfig` 的 Region/Codec 同步补齐键。
- 新增测试：`sites/yemapt_region_test.go`（region 键命中 8 例）、`sites/yemapt_config_test.go`（**加载真实 yemapt.yaml**，断言 source.china→1 / movie→4 / webdl→1 / video.h265→2 / audio.aac→1 / dts_hd_ma→4 / r2160p→7，并断言 tv_series 目前未配置需告警）。
- 待用户抓包确认后补：**电视剧的 category value**、**H.264 的 codec value**、以及其他地区（港台/日韩/印/法等）的 region value。

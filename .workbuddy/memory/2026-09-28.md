## 修复：源站误标「国语」标签（以 MediaInfo 音轨语种为准校正）

**现象**：屌丝（DS）站种子 `Until We Meet Again 2026 S01 1080p HMV WEB-DL AAC2.0 H.264-DepWeb` 被打上「国语」标签，但文件只有一条 `AAC LC` 音轨且 `Language : English`。

**根因链（已实测逐步排除）**：
1. MediaInfo 解析路径**排除**：`ExtractRawTagsFromMediaText(该 MI, false)` = `[英语 外语]`，不产国语。
2. 真正入口 = **源站详情页「标签」字段本身就挂着「国语」**：
   `review_extract.go:1357` `findDetailValueCellByLabels(["标签","標籤","tags",...])` → walk span/a → `appendTag`，只做 trim + 忽略「官方/官种/首发/自购/自抓/应求」（`shouldIgnoreSourceTag`），**不校验语种**。
   → `data.Tags` → `types.go:121 "标签"` → `source_params.标签` → 发布侧 `basic_fields.go:365 collectAllTags` 直接并入提交标签。
3. 另发现三个潜在放大器（**本例未触发，但仍是真 bug**，待定夺）：
   - `mapping.go:166 matchPartial` 双向 `strings.Contains` → 短 raw（如 `国`）反向命中 `tag.国语`。实测 `["国"]`/`["全景声国语"]`/`["京国语"]` → `tag.国语`；`["中文"]` 反而 unmapped。
   - `completion.go:143-151` `splitByCommonDelimiters` 单字 `陆`/`国` 直接产国语（实测副标题 `陆/日/台/粤/闽` → `[国语 台配 粤语]`）。
   - `recompute.go:30` `existingTags` 作为候选来源 → 误标自我固化（实测 `["tag.国语"]` 重算后仍在）。

**用户决策**：用 MediaInfo 校正源站语种标签（以 MediaInfo 为准）。**方案讨论中出现的更激进选项「MediaInfo 与源站语种合并（OR 并集）」被否定**——会把国产片（音轨只有 English、源站标国语）误判为双语，故不采用。

## 截图候选生成报「访问候选路径失败: stat … no such file or directory」的定位口径

- 文案出处在 `processing/media/iso_session.go:237`（`resolveMediaAccessForCandidate` 的 `os.Stat`），外层包装在 `:208/:221`「未找到可用于分析的媒体文件: <source>[<path>] => <err>；…」。
- 入口是 CrossSeedPanel（交叉做种面板）的「生成候选截图」→ `repair/screenshot_preview.go:GenerateScreenshotPreviewCandidates`。链路：`DecideProxy`（下载器 `use_proxy`）→ 代理分支失败/未启用 → `shouldSkipLocalScreenshotFallback` 只在 **decision.Enabled 且 translated==savePath** 时短路报「已停止本地扫描」→ 否则 `resolveLocalMediaTargetResult`（内部先 `TranslateDownloaderPath`）→ `buildMediaPathCandidates` 生成 3 个候选：`save_path/torrent_name`、`save_path/content_name`、`save_path`。
- `downloaderclient/path_mapping.go:63`：**映射未命中就原样返回下载器远端路径**，所以 `no such file` 里出现的是下载器机器上的路径（如 `/home/yuanbao/qbittorrent/Downloads/...`），不代表 PTNexus 上真有这个挂载。
- `repair/screenshot.go:566 enrichScreenshotSourceFromDownloader` 会用下载器实时 `content_path`（优先，`preferExact=true`）覆盖前端传的 savePath；匹配不上会打「截图路径回填未命中」，此时用的是种子记录里的旧快照。注意 content_path 已含目录层，再 join 同名 torrentName 会产出重复一层的冗余候选（无害）。
- 三个候选全部 ENOENT = 父目录整体不可见/不存在，优先查三件事：① server 容器/异机看不到下载目录（bind mount 缺失）② path_mappings 未配或 remote 前缀对不上 ③ 目录真被搬走（MoviePilot 整理/手动 mv，qB 的 content_path 不随外部移动变）。
- 补充（同日 22:54 再次出现同一报错，仍未解决）：`For.All.Mankind.S02.2021...FROGWeb`。三条里第 3 条 `save_path` = content_path 本身也 ENOENT，这条是**唯一有效候选**，故可排除候选构造问题，锁定「server 进程看不到该目录」。注意 `media/iso_session.go:306 buildMediaPathCandidates` **不接收** `preferExactPath`（代理侧 `buildRemotePathCandidatesForProxy` 有），所以 content_path 被当 savePath 后仍会先拼 `+torrentName`/`+contentName` 两条冗余候选，只为日志噪音，非根因。
- 环境线索：OVH 主站登录用户是 `debian`，报错路径是 `/home/yuanbao/...` → 报错来源很可能不是 OVH 主站容器，而是盒子/本机上的 server 进程，待用户确认部署形态（是否与 qB 同机、qB 是否在 Docker 内）。

## sites_data.json 的 `migration` 语义

站点在**转种链路里的角色**，0–3 枚举（bit0=源站、bit1=目标站）：

| 值 | 含义 |
|---|---|
| 0 | 不参与转种 |
| 1 | 仅源站（可拉取源数据，需 cookie/passkey） |
| 2 | 仅目标站（可接收发布，需 passkey/api_key） |
| 3 | 源站 + 目标站 |

- 写入：仅启动同步 `SyncSitesFromJSON`（`repository/sites_sync.go:43`，由 `bootstrap/app.go:50` 调用）。
  前端站点设置页 `SiteRepository.UpdateSiteDetails` 的 UPDATE **不含 migration**，改不了角色。
- 读出：`repository/site_repository.go:247-248` → `/api/sites/status` 的 `is_source`(1|3) / `is_target`(2|3)。
- 门禁：`acquire/fetch/source_site.go:30`（非 1|3 → 403）、`publish/workflow/publish_with_context.go:48`（非 2|3 → 403）。
- 聚合：`service/torrentdata/data.go:31`（targetSites = 2|3）、`filtering.go:74`（源站=1|3 且有 cookie）。

## 馒头「设了 3 但没成为目标站」根因

`sites_data.json` 第 1189 行有 `/*  { ... "site": "yhpp" ... },*/` JS 注释块 →
`json.Unmarshal` 报 `Expecting value: line 1189` → `SyncSitesFromJSON` 整体返回 err →
**整个文件一条站点都不写库**，馒头 `migration=3`（JSON 第 23–31 行）从未进过 DB，
库里保持旧值（DDL 默认 `1` = 仅源站）→ `is_target=false`。

关键点：Go 的 `json.Unmarshal` 不会部分生效，注释块在文件任何位置都会废掉整份同步；
`app.go:51` 原来只是 `Warnf` 一行，极易被忽略。

# 新增目标站点：北洋园（tjupt.org）

**它不是标准 NexusPHP 表单**——判别依据与处理路径已补进 skill `ptn-publish-site-setup`。

## 站点形态（2026-09-29 实测）

- `upload.php` 只有 4 个 select（`type`/`color`/`font`/`size`），**没有** `medium_sel`/`codec_sel`/`standard_sel`/`source_sel`/`team_sel`。
- 分类 = 一级分类 `type`（401 电影 / 402 剧集 / 403 综艺 / 404 资料 / 405 动漫 / 406 音乐 / 407 体育 / 408 软件 /
  409 游戏 / 410 其他 / 411 纪录片 / 412 移动视频）+ 二级分类 `specificcat`（由 `GET showcategorydetail.php?catid=<一级ID>`
  动态下发到 `#class2`）+ 一批**文本字段**（页面上是「快捷 checkbox 拼进文本框」，服务端只认文本）。
- 各一级分类字段集**不同**：401=cname/ename/district；402=cname/specificcat；403=cname/ename/district/issuedate；
  405=ename/specificcat/format/district/issuedate/animenum/substeam(+resolution)；406=hqname/artist/specificcat/format；
  408=cname/specificcat/format/platform…（`*` 为必填）
- 结论：通用 `form_fields`+`mappings` 无法表达「按分类切换字段名与值域」→ **必须专属适配器**。
- 站点**没有 `name` 主标题字段**，主标题由服务端从种子文件读取；中文名/英文名分开填 `cname`/`ename`。

## 站点校验规则（前端 `assets/js/upload-validation.*.min.js` 实测）

英文名 = 0Day 名、中文名 = 单个大陆译名；`cname`/`ename` 不得带文件扩展名；`cname` 不得含 `/`、不得含「共X集/全X集/第X集」；
`cname` 应含中文、`ename` 不应含中文；405 的 `ename` 不得含 `x264/x265/avc/hevc`；403 `issuedate`=YYYYMMDD(或 YYYY)，
405=YYYY年MM月；404 `specificcat` 限站点列表内且 ≤2 项；`district`/`specificcat` 全为华语地区时不得勾 `chinese`；
`ename` 以 `-TJUPT` 结尾（405 看 `substeam` 以 TJUPT 结尾）时必须勾 `tjuptrip`。

## 再补充：北洋园「动漫资源一律不发布」+ 站点级硬性拒绝统一 PreCheckError（同日追加）

**需求反转**：上一轮做的「标签含动漫 → 一级分类强制归 405」被否定 —— 北洋园**整类不接收动漫资源**，
命中即拒绝，不再改写分类后硬发。

改动（3 个文件 + 1 个新文件）：
- 新增 `server/internal/service/publish/publisher/precheck.go`：`PreCheckError{Reason}` / `NewPreCheckError` / `AsPreCheckError`。
  语义 = **确定性拒绝**（未发起上传请求，重试必然同样失败）。
- `sites/tjupt.go`：删除 `animationByTag` 覆盖逻辑，改为入口处 `resolveTJUPTAnimeRestriction(cfg, input)`——
  ① 一级分类映射 405；② `hasAnimationTag` 命中 → 返回 `publisher.NewPreCheckError("北洋园不接收动漫资源：…")`。
  判定放在 `loadTJUPTConfig()` 之后、**读种子文件与 UPLOAD_TEST_MODE 之前**（本地测试模式也拦）。405 字段装配分支保留但正常不可达。
- `workflow/publish_entry.go`：`publishErr != nil` 分支里 `publisher.AsPreCheckError(publishErr)` 命中 →
  `buildPreCheckFailure(reason)` → 返回 `success:false + pre_check:true + limit_reached:true`（status 200）。
- `sites/ourbits.go`：我堡 Remux 一并从 `errors.New` 改成 `NewPreCheckError`（同类语义，原来会被当 500 失败重试）。

**为什么必须 PreCheckError**：队列侧（`migrationflow/publish_queue.go`）只对
`pre_check && limit_reached` 走 `notifyScheduledSeedContinue(..., countAsSkipped=true)` →
`MarkResultAsSkipped` → `ReclassifyPublishedAsSkipped`（published-1 / skipped+1）；普通 error 会变成 500 失败进重试，
耗尽后才由「重试超限」补记跳过 —— 统计最终收敛但白跑重试、日志里还多一堆假失败。

验证：`go build ./...` + `go vet ./internal/service/publish/...` 干净；临时 httptest 19 个用例全绿，
其中动漫拒绝 7 例（标签四路 + 类型两路 + 源站标签路）断言「err 是 *PreCheckError + 上传次数=0 + 无字段装配」，
非动漫 4 类（401/402/403/411）断言正常发布且无动漫专属字段（防误伤），另有 `errors.Join` 包装后仍能识别的链路用例。

### 提交 1：`8da54b8` MySQL DSN 时区钉死

### 提交 3：`ab92338` 修复 AfterFind 钩子签名
- **根因**：提交 1+2 部署后，老卫报时间显示成 `2026-09-27T11:25:24+08:00`（CSS 换行成两行）——值正确（+08:00 = 北京时区）但格式没归一。
- **链路**：MySQL DATETIME → go-sql-driver `parseTime=True` → `time.Time` → `database/sql` 扫入 `*string` 用 `RFC3339Nano` 格式化 → `2026-09-27T11:25:24+08:00`。
- **修复**：`PublishQueueTask` 加 `AfterFind(tx *gorm.DB) error` 钩子，读出后调 `normalizeQueueTimeString` 归一到 `PublishQueueTimeLayout`。⚠️ **GORM 钩子参数必须是 `*gorm.DB` 指针**——初版写成 `gorm.DB` 值类型被 GORM 静默跳过，钩子从未执行。sqlite 内存库单测验证：7 种形态（原始/RFC3339/RFC3339Nano/UTC/time.Time.String()/带纳秒/空）全部归一正确，钩子确实被调用。前端同时保留 RFC3339 兜底（双保险）。
- `parseQueueTime` 原 `new Date(year,...)` 按浏览器时区解析北京墙钟，浏览器不在东八区时相对时间差 8h。改为拼 `+08:00` 偏移的 ISO 格式让 JS 按北京时区解析为正确时间戳。

## 功能：进度页 dispatched 任务单站立即发布/取消（已提交 d8ec828）
- 老卫需求：进度页「待发布」里 dispatched（立即发布批次登记）的行也要能立即发布和取消。
- **BatchState**（`publish/workflow/batch_state.go`）新增 `handled map[batchID]map[site]bool` + `MarkSiteHandled`/`IsSiteHandled`：站点级跳过标记。
- **三种 runner**（serial/concurrent/paced）`BatchRunnerDeps` 新增可选 `IsSiteSkipped func(site)`，执行站点前检查，跳过已站外处理的站点；`batch_execute.go` 的 runnerDeps 接 `State.IsSiteHandled(batchID, site)`。
- **新增 `publish_batch_dispatch_ops.go`**：
  - `CancelDispatchedTask(id)`：校验 dispatched → `MarkSiteHandled`（批次仍在跑才有效）→ `MarkDispatchedCancelled([id])`（count=0 说明 runner 已领取，返回 409）→ 同步 publish_logs。批次已结束也能取消（纯 DB 操作）。
  - `PublishDispatchedTaskNow(id)`：校验 dispatched + `liveBatches[batchID]` 存在（服务重启后丢失 → 409）→ `MarkSiteHandled` → **复查 DB 状态防双发**（标记后 runner 仍可能在几 ms 窗口内领取）→ 站外 goroutine：复制 payload + `targetSite=site` 调 `s.Publish`，`tracker.progress(started/finished)` 回写队列记录，`MarkSiteResult`+`Emit` 同步发布面板 SSE。
- **分流**：`PublishQueuedTaskNow`/`DeleteQueuedPublishTask` 按 status 分流（queued 原路径 / dispatched 新路径），复用既有路由无新端点。
- **`MigrateService.liveBatches`**（types.go）：batchID → {tracker, payload}，`StartPublishBatch` 注册、`runPublishBatch` 结束后删除（goroutine 内 cleanup）。
- 前端 `PublishProgressView.vue`：`isRowActionable(row)` = queued||dispatched，两个按钮 + tooltip 对 dispatched 开放；取消确认文案区分两种状态。
- 测试（zz_tmp，已备份 `.workbuddy/tmp/test-backup/zz_tmp_dispatch_ops_test.go` 后删除）：三 runner 跳过行为、BatchState 标记/隔离/空白名、404/409 校验分支、dispatched 取消落库、无上下文立即发布 409。
- ⚠️ 遗留边界：paced runner 波内全部站点被跳过时仍会等 interval 再进入下一波（跳过执行是瞬时的，影响小）；批次结束后 `liveBatches` 已删，取消仍可用但立即发布 409。

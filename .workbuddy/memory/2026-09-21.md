## 馒头（M-Team）发布站点接入 + 线上两个 bug 修复

**背景**：先是接入 m-team（kp.m-team.cc，API Access Token `57b1fa6c-...`），
当晚用户实测发种失败，日志报 `key無效` + 三项「映射未命中」，本次修复。

**根因 1：映射未命中（standard / videoCodec / audioCodec 全回落 defaults）**
- 适配器先把标准化值用 `normalizeMTeamToken(raw, "resolution.")` 削成 `r1080p` 再去查字典，
  而 yaml 只写了 `resolution.r1080p`；`pick` 的「去前缀兜底」对已无点的键无从下手 → 必然回落。
- 修法：字典查找一律传**原始完整标准化值**，去前缀形态只用于分类落点判断；
  并在 `loadMTeamConfig` 里派生去前缀别名（`expandMTeamAliases`），两种上游形态都能命中。
- yaml 因此简化为「每个维度只写一套带前缀完整值」，删掉原来 source 段的重复双形态。

**根因 2：`key無效`（令牌被解析成了错误的值）**
- 用真实令牌直接调 `/api/torrent/categoryList` 返回 SUCCESS，说明令牌本身有效。
- 写临时 live probe（真实令牌 + 真实种子 + **无效分类 999999**）走 Go 代码路径
  `postMTeamTorrent`，返回「指定的類目不存在」→ 证明代码送出的鉴权头/字段/文件全对，
  问题只在「用户填的内容被解析错」。
- 原因：`resolveMTeamAPIKey` 在无法识别时 `return strings.Trim(raw, "'")` **整串兜底**，
  用户按老习惯往 Cookie 栏粘的网页 Cookie 被整串当成 x-api-key 发出，日志毫无提示。
- 修法：`resolveMTeamToken` 三来源候选（`TargetInfo["api_key"]` > `passkey` > `cookie`）
  + `extractMTeamToken` 三段式解析（键值前缀 → 正则捞 UUID → 纯串），
  **明确拒绝网页 Cookie**（含 `=` 的 key=value 形态三段都不命中 → 返回空 → 上层报错提示）；
  发布日志加脱敏指纹 `API Token: 57b1fa6c…(长度 36)（来源 X 栏）`。
- 关键背景：前端 `SitesSettings.vue` 的 `needsPasskey = ['hddolby','m-team','hdtime','rousi']`
  会把 m-team 显示成「需要手动配 Passkey」，用户可能填在 Passkey 栏 —— 两栏都要取。

**顺带修掉**：`cfg := mteamDefaultConfig` 后直接 merge 会就地改写**全局兜底字典**
（map 是引用类型），并发发种时 data race；改为逐张 `cloneMTeamMap`。

**改动（3 个文件）**
1. `server/internal/service/publish/publisher/sites/mteam.go` — 映射传完整值、`resolveMTeamToken`
   /`extractMTeamToken`/`mteamTokenFingerprint`、`cloneMTeamMap`、`expandMTeamAliases`、日志指纹
2. `server/configs/mteam.yaml` — 三个维度恢复单一形态（去前缀别名由代码派生）
3. `server/internal/service/publish/publisher/sites/mteam_config_test.go` — **新增并保留**（纯单测，
   含「网页 Cookie 必须被拒绝」「多次加载不污染全局」断言；无网络依赖）

**验证**：`go build ./...` 通过；6 个单测全绿；live probe 实测站点返回「指定的類目不存在」
（鉴权与字段格式全部通过，分类无效故不会真发种）—— 探测文件带真实令牌，用完即删。

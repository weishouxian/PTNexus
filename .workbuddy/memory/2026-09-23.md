## 代码调研：种子简介 / 海报的获取链路（只读，未改代码）

**三段式：源站解析 → 兜底补全 → 资源库复用**

1. 源站解析（`acquire/extract/review_extract.go`）：`extractReviewDataFromHTMLWithSite()` 取 `#kdescr`（div 优先，回退 td）→ `htmlToBBCode()`；`extractDescriptionSections()` 里 `splitPosterAndScreenshots()` 从简介所有图片中挑海报——**优先含 `doubanio`/`tmdb`/`poster` 关键字的图，否则第一张**，其余为截图；正文走 quote 块流程 `buildBodyFromQuoteFlow`。另有 `#ktext` 走 `extractExtraTextBBCode` 作声明源。
2. 修复阶段（`processing/repair/fetch_flow.go` `RunParallelFetchRepairs`）：海报/简介/截图三路并发。海报先 `IsImageURLReachable` 校验，无效才兜底；简介用 `checkIntroBodyCompleteness` 查 **`introCriticalFields = {片名, 产地, 简介}`**（`intro_completeness.go`），缺了才兜底。⚠️ NovaHD 源站简介直接沿用源站、跳过补全（`isNovaHDSourceSite`）。
3. 兜底 `FetchMovieInfo(mediaType, ...)`（`repair/movie_info.go`）按优先级：PTGen（CSPT token → 4 个自建/公益节点，`buildPTGenCandidates`）→ 豆瓣页（og:image / `a.nbg img`；`span[property=v:summary]` / meta desc）→ TMDb API（`api.tmdb.org`/`api.themoviedb.org`/两个 worker 代理，poster_path → `image.tmdb.org/t/p/original`）→ IMDb 标题页（og:image / og:description / JSON-LD）。外链互补靠 imdb2douban worker 桥 + TMDb `find` API。简介统一由 `BuildIntroText()` 组装（【简介】+标题+正文+来源链接行），PTGen 结果会补「TMDB链接」行。
4. 海报落地 `NormalizePosterBBCodeWithConfig()`（`repair/pixhost.go`）：按 `image_hoster` 分流，`agsv` → Chevereto 末日图床，默认 → Pixhost（`api.pixhost.cc`），失败回退原 URL，最终统一成单个 `[img]url[/img]`。
5. 资源库（`persist/fetch_resource_info.go`）：`RunFetchRepairAndFinalize`（`fetch_repair_finalize.go`）里修复完再查 `resource_info`，命中 `ApplyResourceInfoToDraft` **只覆盖 Poster + Body**，标题/产地/截图保持本次抓取值；未命中 `SaveResourceInfoFromDraft` 入库（已存在不覆盖）。预览路径走 `db_seed_query.go` 的 `AttachResourceInfoToRow`；转种面板保存走 `migrationflow/db_seed_update.go` → `SyncResourceInfoFromParams` **强制覆写**。
6. ⚠️ 海报格式两套：`resource_info.poster_url` 存**纯 URL**，草稿存 **BBCode**，互转靠 `repository.WrapPosterURL()` / `normalizePosterURL()`。

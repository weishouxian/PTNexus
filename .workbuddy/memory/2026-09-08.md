### 6. SQLite 并发锁冲突修复
- **问题**：多个后台服务（发布队列、种子刷新、自动发种、定时发种）并发写入 SQLite 时报 `database is locked (SQLITE_BUSY)` 和 `cannot start a transaction within a transaction`
- **根因**：
  1. 没有设置 `busy_timeout` — 写锁被占用时立即失败而非等待
  2. 没有开启 `WAL` 模式 — 默认 rollback journal 模式下读写互斥
  3. `MaxOpenConns(20)` — SQLite 只支持单写入者，多连接争抢锁导致嵌套事务错误
- **修复**（`server/internal/repository/db.go`）：
  1. SQLite DSN 加 `?_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)&_pragma=synchronous(NORMAL)`
  2. SQLite 时 `MaxOpenConns(1)` + `MaxIdleConns(1)`，序列化所有 DB 访问，避免连接池复用已在事务中的连接
  3. MySQL/PostgreSQL 保持 `MaxOpenConns(20)`

## 修复 torrents.details 没值（方案C：autoseed 写入 .torrent comment）

根因：RSS 拉取/自动发种发布的种子在 torrents 表 details 为空。autoseed 下载/发布种子时从不写 comment；下载器同步（`SyncDownloaderTorrents`）的 OnConflict DoUpdates 含 `"details"`，每轮用 `extractDetailFromComment(comment)` 解析出的值无条件覆盖；comment 拿不到（autoseed 不写 + qb 直连 qb5.0 前无 comment 字段），details 被空值覆盖。发布回写 `UpdateTorrentDetailsAfterPublish` 还有"无 site 按 hash"fallback 会打偏源站行。

方案C实现（用户选定）：autoseed 下载/发布种子时把详情页 URL 写进 .torrent 的 comment 字段，下载器同步时 `extractDetailFromComment` 即可提取。
- `server/internal/service/acquire/fetch/torrent_comment.go`（新文件）：`RewriteTorrentComment(content, comment)`，字节级扫描 .torrent 顶级字典，按 bencode key 字典序重组，**info 用原始字节保证 infohash 不变**，comment 用新值；comment 为空时保留原值。
- RSS 拉取线（`autoseed/service.go`）：新增 helper `rewriteTorrentCommentIfNeeded(path, detailURL)`，三处下载种子点在 `AddTorrentFileWithOptions` 前，用 `fetchResult["detail_url"]`（源站详情页）重写本地 .torrent comment。
- 发布线（`publish/workflow/publish_entry.go` + `publish/downloader/add.go`）：addPayload 增加 `publishURL` 字段；add.go 在 `DownloadTorrentForSource` 下载字节后、`AddTorrentDataWithOptions` 前，读 `payload["publishURL"]`（目标站详情页）重写 comment。

验证：`go build ./...` 通过。

⚠️ 方案C前提与局限：
- 依赖下载器能读到种子的 comment 字段（qBittorrent 5.0+ 的 torrents/info 返回 comment，或走代理 `include_comment`）。若下载器读不到 comment，details 仍会空。
- 仅对新拉取/新发布的种子生效；已入库旧种子的 .torrent 已加到下载器，comment 未写，details 仍空（需靠 UpdateIYUUCheckAndFillDetails 或手动编辑回填）。

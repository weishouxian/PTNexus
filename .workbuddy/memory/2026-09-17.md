## YemaPT imdb 参数：只发纯数字（剥掉 tt 前缀）

**需求**：用户要求「imdb 传参需要把 tt 去掉」。

**现状核对**（只读 `GET /api/torrent/fetchTorrentDetail?id=...`）：站点上 5 条种子实测 imdb 全是纯数字 —— 14791=`35221148`、14875=`0206013`、14886=`2446042`、14887/14888=None，即旧逻辑（`tt(\d+)` 正则提数字）本来就没把 tt 发过去。

**真正缺口**：`resolvePublishExternalLinks` 只聚合 `imdb_link/imdbLink/imdb`，**不读 `imdb_id`**。而 PTNexus 内部 `resource_info.imdb_id` 的规范形态就是 `tt+数字`（见 `repository/resource_info.go` 注释），转种面板回传时若只有 `imdb_id`，此前会**整个 imdb 字段都不发**。

**改动**（`server/internal/service/publish/publisher/sites/yemapt.go`）：
- 新增 `resolveYemaPTIMDbParam(input, std)`：按优先级聚合 `input.IMDbLink → std.imdb_link/imdb/imdb_id → uploadData.imdb_link/imdb/imdb_id`，逐个走 `extractYemaPTIMDbID`，**始终返回纯数字**。
- `reYemaPTIMDb` 改为大小写不敏感 `(?i)tt(\d+)`（`TT0206013` 也能剥）。
- 发布日志新增一行 `外链字段: imdb=%q douban=%q`，可直接核对实际提交值。
- 新增 `yemapt_imdb_test.go`：13 例 ID 提取（含大/小写 tt、完整链接、带查询串、非 IMDb 链接）+ 7 例来源优先级；断言结果**永不包含 tt**。
- `go build` / `go vet` / `go test ./internal/service/publish/... ./internal/service/acquire/...` 全绿。

**注意**：站点详情里 imdb 是纯数字，是指向 `https://www.imdb.com/title/tt{imdb}`；若把 tt 一起发过去会变成 `tttt...` 非法链接。

**状态**：改动未提交，需重新构建部署 server 才生效。

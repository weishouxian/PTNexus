## 排查「改了 CHANGELOG 为什么 app 不提示更新」

**结论：不是 bug，是 Release 还没构建。** v4.0.4 只写进了 `CHANGELOG.json`（已 push），但更新提示读的是**远端 Release 附件**，`releases/latest` 仍指向 v4.0.3（10-10 22:40 发布）。本地版本 = 远端版本 = v4.0.3 → 无提示。

**更新检测链路**（`updater/updater.go:checkUpdateHandler`）：
1. `getRemoteManifest()` 只从 **Release 附件**取清单，候选顺序：`UPDATE_MANIFEST_URL` 环境变量 > `github.com/.../releases/download/<version>/UPDATE_MANIFEST.json` > `gitee.com/wsx181/.../releases/download/<version>/...` > 两边的 `/releases/latest/download/...`（`update_sources.go`）。
2. 比对 `manifest.latest.version` 与 `getLocalVersion()`（本地版本来自当前运行时推断，退化为 `localVersionConfigCandidates()` → Docker 下是镜像内 `/app/CHANGELOG.json`）。
3. 强更标记：`latest.force_update` / `latest.disable_update` / `history[].force_update`（`hasCrossVersionForceUpdate`；本地版本不在 history 里时**不做跨版本强更推断**）。

**⚠️ 仓库根目录的 `UPDATE_MANIFEST.json` 是死文件**：内容停在 v4.0.2，**全仓没有任何脚本或运行时代码读它**（grep 只命中 CI 生成路径 `dist/updates/<version>/UPDATE_MANIFEST.json` 与 updater 的文案）。真正的清单由 CI 现场生成：

## 排查「定时发种表格横向滚动条没有了」

- 用**无头 Chrome + 真实 Element Plus**（`node_modules/element-plus/dist/index.css` + `index.full.js` + `vue.global.prod.js`）搭了个离线复现页，再用 `--dump-dom` 把测量结果写进 DOM 读出来。这个套路对「只在浏览器里才看得出的布局/滚动问题」非常有效，值得复用：

- 结论：**不是我们代码的问题，是 Element Plus 的默认行为** —— 滚动条只在鼠标移到表格上时淡入。证据（`es/components/scrollbar/src/thumb.vue_...mjs`）：
  ```js

  const mouseMoveScrollbarHandler = () => { visible.value = !!props.size }   // 监听 .el-scrollbar 的 mousemove
  ```

## 截图失败：DoVi P5 源 zscale 报 3074（仅诊断，未改代码）

**根因**：该 mkv 视频流是 `hevc Main 10, yuv420p10le(pc)` + `DOVI configuration record: profile 5` = **Dolby Vision Profile 5**，像素用 Dolby 私有 **IPTPQc2（IPT+PQ）** 编码，不是标准 YCbCr。zimg（zscale 底层）没有 IPT↔linear RGB 的转换路径 → 报错（3074 属 zimg 色彩空间类错误码）。与位深/range 无关，`(pc)` 只是 full range。

**链路**：日志形态（无 `-v error`、输出 image2/mjpeg、`-ss` 前置快速定位）对应**预览抽帧**两条链路之一：
- `proxy/media_core.go:takePreviewScreenshot`（第 259-274 行）
- `server/.../repair/screenshot_preview.go:capturePreviewJPEGWithFFmpeg`（第 757-786 行）
两者 HDR filter 相同：`zscale=t=linear:npl=100,format=gbrpf32le,zscale=p=bt709,tonemap=tonemap=hable:desat=0,zscale=t=bt709:m=bt709:r=tv,scale='min(640,iw)':-2,format=yuv420p`。

⚠️ **这两个函数都没有降级链**（失败即丢帧）。只有 `compressPNGWithFFmpeg` / `convertPngToOptimizedImage`（输入是 mpv 导出的 PNG）才有 explicitHDRFilter 重试 + `scale` 兜底；且其 `explicitHDRFilter` 写死 `pin=bt2020:tin=smpte2084`，对 P5 同样无效。

**修法方向**（待用户定）：
1. 正解：`libplacebo`（需 ffmpeg 带 libplacebo+vulkan，原生支持 DoVi P5 IPT）：`libplacebo=tonemapping=hable:colorspace=bt709:color_primaries=bt709:color_trc=bt709:range=tv:format=yuv420p`。
2. 一致性方案：预览链路改走 mpv（项目已有 `captureRawPNGWithMPV`，mpv 原生 tonemap DV）。
3. 兜底：ffprobe 检出 `DOVI ... profile: 5` 时跳过 zscale，直接 `scale=...,format=yuv420p`（偏色但可用）。

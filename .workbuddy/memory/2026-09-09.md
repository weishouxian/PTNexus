## 修复定时发种任务编辑报 MySQL 1292

- 现象：编辑定时发种任务报 `Error 1292 (22007): Incorrect datetime value: '2026-09-08T11:06:47Z' for column 'next_run_at'`。
- 根因：报错值带 `T`/`Z` 后缀（RFC3339 / ISO 8601 UTC 格式），MySQL DATETIME 列不接受。线上 server 二进制为旧版，旧 handler 未对 `next_run_at` 做格式归一化即写入 UPDATE。
- 修复：`server/internal/repository/scheduled_seed_repository.go` 新增 `normalizeNextRunAt()`，在 `Create`/`Update` 入口把任意常见格式（空格分隔 / T 分隔 / RFC3339 / RFC3339Nano / 带 Z / 纯日期）统一转成 `2006-01-02 15:04:05`，解析失败回退当前时间。repository 层兜底，覆盖所有写入路径（含历史 `0000-00-00` 零值也会回退为 now）。
- 验证：`cd server && go build ./...` 通过（exit 0）。
- 后续：需重新编译部署 server 二进制才能让修复在线上生效。

## 媒介判定：标题声明 WEB-DL 即强制媒介为 WEB-DL

- 背景：用户发现 dstudio.me 上标题带 WEB-DL 的种子被判定为媒介 Encode(因 mediainfo 视频轨出现 x264 重编码特征)。需求：标题写 WEB-DL 时媒介也设为 WEB-DL。
- 根因：旧 `PreferExplicitTitleMedium` 只在当前媒介是 weak 值(`medium.other`/`medium.encode`/`encode`/`other`)时才用标题覆盖；来源站若把 Encode 映射成带后缀键(如 `medium.encode_1080p`)就不在 weak 列表，导致落库成 Encode。
- 修复：`server/internal/service/processing/title/simple_components.go` 的 `PreferExplicitTitleMedium` 在 weak 判断前新增 `titleDeclaresWebDL(title)` 短路，命中即返回 `medium.webdl`。两处调用点(seed_draft.go、seed_component_rewrite.go)均受益。
- 验证：新增 `simple_components_test.go`(5 用例全过)；`go build ./internal/service/processing/title/` 通过。
